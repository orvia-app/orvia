# Orvia Branding And Naming

## Current Visible Brand

Current visible product name: Orvia.

Orvia replaces the prior working name, Archflow, for visible product branding in the app, README, and project docs. Treat this as Rebrand Phase 1: visible naming changes only.

External brand validation is still required before domain purchase, public beta, production infrastructure naming, Telegram bot creation, or App Store preparation.

## Why Orvia Still Needs Validation

Orvia fits the current product direction because it is short, calm, and abstract enough for a productivity operating system. It may still be risky because:
- domain and social handle availability are unknown
- trademark conflict risk has not been reviewed
- App Store and Telegram handle suitability has not been checked
- search/SEO conflict risk has not been reviewed
- production projects, domains, and public assets become harder to rename later

Do not purchase domains, name production Supabase projects, create public Telegram bots, or prepare App Store assets until validation is complete.

## Naming Criteria

The final name should be:
- short
- memorable
- premium
- calm, not noisy
- suitable for AI/productivity without generic AI hype
- suitable for a web app, mobile app, and Telegram bot
- easy to pronounce
- easy to spell from hearing
- searchable
- low-conflict after domain/trademark review
- flexible enough for optional modules and future integrations

Avoid:
- names that overclaim AI capability
- names that sound like an enterprise admin tool
- names that are too close to existing productivity, AI, notes, workflow, or automation products
- names that rely on awkward spelling
- names that feel childish, novelty-driven, or hard to trust with personal data

## Product Positioning To Preserve

The name should support these product ideas:
- calm AI operating system
- capture -> organize -> recall -> act
- local-first and privacy-first
- memory/context as the product moat
- command-first productivity
- user-owned data
- optional modules and integrations
- future mobile and Telegram capture

The brand should feel trustworthy enough for personal notes, work context, finance-adjacent records, and future AI memory.

## Candidate Naming Directions

These directions are retained for future comparison if Orvia fails external validation.

### Memory

Names in this direction should suggest recall, continuity, and personal context without sounding clinical or surveillance-heavy.

Watchouts:
- avoid names that imply hidden or permanent memory
- avoid overused "memo", "mem", or "mind" combinations unless distinct

### Flow

Names in this direction should suggest movement from capture to action.

Watchouts:
- many workflow/productivity names already use "flow"
- avoid sounding like a process automation tool only

### Mind

Names in this direction should suggest thinking, organization, and personal intelligence.

Watchouts:
- "mind" names can feel generic in AI
- avoid sounding like therapy, wellness, or medical software unless intentional

### Recall

Names in this direction should emphasize finding and resurfacing what matters.

Watchouts:
- ensure the name does not sound like legal discovery, surveillance, or a backup utility

### Context

Names in this direction should highlight connected work, entities, timeline, and memory.

Watchouts:
- "context" can sound technical or developer-focused
- consumer pronunciation and warmth matter

### Calm Productivity

Names in this direction should feel quiet, focused, and premium.

Watchouts:
- avoid names that become too abstract to explain
- avoid bland wellness/productivity overlap

### Archie / Parrot-Inspired

This direction can nod to "Archie" or a companion-like memory/capture concept without becoming childish.

Watchouts:
- avoid cartoon mascot dependency
- avoid names that undermine trust for serious personal/work data
- keep the brand premium, minimal, and evolvable

## Evaluation Checklist

Before choosing a final brand, check:
- Domain availability for primary options, ideally `.com` or a credible product domain.
- Trademark risk in target markets, especially US/EU software and productivity categories.
- Pronunciation in conversation.
- Spelling after hearing the name once.
- SEO/searchability against existing products and common terms.
- App Store suitability and conflict risk.
- Telegram bot handle suitability.
- GitHub/org/project naming suitability.
- Social handle availability where relevant.
- Visual identity fit for app icon, wordmark, and monochrome UI.
- International readability for US/EU audiences.
- Whether the name still works if finance, cars, automation, or integrations are optional modules.

This checklist is not legal advice. A serious finalist should receive professional trademark review before public launch.

## Decision Timing

Complete Orvia validation before:
- buying a domain
- naming production Supabase projects
- naming Vercel production projects if public-facing
- launching public beta
- creating Telegram bot handles
- preparing App Store or Play Store assets
- creating public social accounts
- publishing launch or investor materials

## Risks Of Delaying External Validation Too Long

Delaying validation too long can cause:
- duplicated renaming work across UI, docs, infrastructure, and marketing assets
- confusing public/private project names
- domain or handle loss
- avoidable trademark conflict
- messy Supabase/Vercel/project naming
- weaker early user recall
- lower confidence when inviting reviewers, testers, or teammates

Internal technical identifiers such as legacy localStorage keys should not be renamed casually. Product-facing brand changes and storage migrations are separate decisions.

## Next Action

Recommended next step:
1. Run web, domain, App Store, Telegram handle, GitHub, and basic trademark searches for Orvia.
2. If Orvia passes, record the decision and reserve public assets.
3. If Orvia fails, create a fallback shortlist of 20-40 candidates across the directions above.
4. Score finalists against the evaluation checklist.
